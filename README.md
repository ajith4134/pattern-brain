# Pattern Brain

A standalone research/architecture project — explicitly **not connected to the trading bot** (`/opt/trading-bot`). Started 2026-06-20, named by the owner.

**Scope:** researching ML/statistical model families for pattern-finding, sequence prediction, probability estimation, noise/signal separation, and synthetic data generation, plus the harder architectural problem of letting many heterogeneous models share input data and exchange outputs (a "universal data translator" + "universal belief space / connector intelligence" design).

**Status:** **implementation started 2026-06-20.** Build-tracker **steps 1 (starter model bank), 2 (Connector Intelligence v0 + the §8 dashboard walking skeleton), 3 (stock-data adapter + the §8 Adapter-View tab), 4 (LLM-tool-calling routing — Connector v1) and 5 (interlingua versioning/drift scheme) are complete** — see `pattern_brain/`, `pattern_brain/adapters/`, `pattern_brain/routing.py`, `pattern_brain/interlingua.py`, and `dashboard/`. The rest of the build order is in `PLAN.md`. See `DISCUSSION_NOTES.md` for the full, growing record of every idea discussed (owner's and Claude's). See `RULES.md` for how this project is run.

**Code (`pattern_brain/`):** a domain-independent model bank. Every node operates on a generic `(T, D)` sequence and emits a `Belief` through one common interface (`fit`/`predict`/`transform`/`process`) — zero candle/order-book coupling (Rule 23). **143 light-stack node types** (numpy/scipy/sklearn) across 8 functional layers (signal, noise, pattern, sequence, probability, equation, decision, rl) — including the **Phase-7e physics/PhD tier** (`pattern_brain/nodes/physics.py`: reservoir computing / Echo State Network + deterministic TCRC forecasters, Lyapunov-exponent & RQA chaos detectors, Hurst fractal, sample/permutation entropy, and Random-Matrix-Theory denoising), **+ 11 optional PyTorch deep nodes** (`pattern_brain/nodes/deep.py`: LSTM/GRU/Transformer/TCN/MLP/diagonal-SSM forecasters, deep + variational autoencoder denoisers/anomaly, and a graph-conv GNN denoiser) → **162 active when torch is installed** (en route to the §11 ~500-node catalog). The deep nodes are an optional dependency (`requirements-deep.txt`): without torch the light bank works unchanged; install torch and they register automatically. Run `python3 demo.py` to watch the whole bank work on a synthetic sequence, or `python3 tests/test_bank.py` for the contract + behavior suite. `pattern_brain/connector.py` adds Connector Intelligence v0: one fixed, hardcoded pathway (`difference -> hdbscan -> gaussian_hmm -> threshold_policy`) threaded end-to-end through the Universal Belief Space — `python3 run_pathway.py` for the terminal view, `python3 tests/test_connector.py` for its tests. Language policy is polyglot by stage (`PLAN.md` §0b): Python now, C/C++ for proven hot paths later. Deps: `requirements.txt` (numpy/scipy/scikit-learn).

**Stock-data adapter (`pattern_brain/adapters/`, build step 3):** the ONE sanctioned home for domain-specific code (Rule 23) — deliberately *not* imported by the core package, so the core stays domain-clean (the dependency only flows adapter → core). It bends real OHLCV candles into the exact same finite `(T, D)` array the bank already consumes (the data bends to the system, never the reverse — `PLAN.md` §0). Three layers: generic numeric tools reusable by any future domain (`frac_diff` — López de Prado fixed-width fractional differentiation, stationary *with memory*; `align_to_grid`/`align_sources` — causal as-of resampling of irregular/asynchronous/differently-sampled sources onto one shared grid, closing the §6 time-asynchrony gap), a validated `CandleSeries` container, and `StockDataAdapter` (the only part that knows OHLCV). Numpy-only, no pandas. `python3 tests/test_adapter.py` for the suite (incl. the adapter output running unchanged through `default_connector()`).

**Routing — Connector v1 (`pattern_brain/routing.py`, build step 4):** the first *dynamic* routing. Instead of the v0 fixed pathway, a `Router` decides the next node hop-by-hop from the bank (nodes presented as "tools"), respecting the Block-18 layer-adjacency constraint, until a decision fires. LLM-tool-calling was chosen first (MoE/GNN need routing-outcome training data that doesn't exist yet). The LLM is a **swappable boundary, not a hard dependency**: `HeuristicRouter` is a deterministic offline default (no API key); `LLMRouter` depends only on one injected `complete(...)` callable, tested with a fake so the whole tool-calling loop runs offline — a real Anthropic/Ollama client drops in later as that callable. `RoutedConnector` reuses the v0 `Hop`/`PathwayResult` so the dashboard/audit consume routed runs identically. `python3 tests/test_routing.py` for the suite.

**Interlingua versioning/drift (`pattern_brain/interlingua.py`, build step 5):** makes the shared belief language explicit, versioned and checkable, so nodes added/retrained later can't silently drift the contract. A versioned **catalog** declares each belief type's required/optional payload keys (the v0.1 catalog is built from what the bank emits, so the bank conforms by construction); `validate_belief`/`detect_drift`/`conformance_report` catch off-contract beliefs (unknown type, missing key, un-migratable version); `register_migration`/`migrate_belief` bridge a version bump; `interlingua_coherence` surfaces the soft finding that some types (action/decision/forecast) have payloads that vary across emitters. `python3 tests/test_interlingua.py` for the suite.

**Dashboard (`dashboard/`):** the §8 living-graph dashboard, ratified stack (Block 43): a FastAPI backend + a single-file React/ReactFlow/Plotly frontend (loaded via esm.sh + an import map — no build step). The dashboard **lands on an Overview** showing the WHOLE system (counts for every subsystem — 123 models, 8 layers, source files, lines, test suites — build status, models-by-layer, and clickable subsystem cards). Tabs: **Overview · Model Bank** (all 123 nodes as a genome map) **· Evaluator** (the 5-layer gate on a demo edge-vs-noise candidate) **· Evolution** (Features 1/2/3 born→tested→promoted feed) **· Living Graph** (the running pathway) **· Adapter** (stock candles) **· Files** (every .py/.html file with line counts + summaries). The Living Graph watches Connector v0's pathway run hop by hop over a WebSocket — nodes glow as they fire, edges animate, a belief-space stream and per-node confidence chart update live, and clicking a node opens its Model-Genome metadata. The core "Living Graph" tab is domain-agnostic (Rule 23): synthetic `(T, D)` data only. A **"Model Bank" tab** (build step 6) shows the *whole* bank — all 60 nodes as columns by functional layer (the genome map), distinct from the Living-Graph tab which shows only the running pathway. A separate **"Adapter View (stock)" tab** (build step 3) is the only stock-specific surface — it shows synthetic candles → the `StockDataAdapter` → the generic `(T, D)` → the *same* core pathway running on it (a candlestick is the lone domain visual on the whole dashboard). Setup (separate venv — these deps aren't in the model bank's `requirements.txt`):
```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dashboard.txt
.venv/bin/python dashboard/server.py        # serves http://127.0.0.1:8077
.venv/bin/python tests/test_dashboard.py    # contract + behavior suite (no live server needed)
```

**Planned features (added 2026-06-20, spec in `DISCUSSION_NOTES.md` Block 14):**
1. **ML Model Creation + Mutation** — create new instances of existing model families and evolve/mutate already-trained models (hyperparameters, architecture tweaks, partial retraining, crossover between two trained models), gated by an automatic evaluator before any mutation replaces an incumbent.
2. **ML Algorithm Creation + Mutation** — a level above #1: discover and evolve genuinely new algorithms/equations (not just new settings within a fixed one), via evolutionary search over program/equation space (AutoML-Zero / FunSearch / AlphaEvolve-style), same automatic-evaluator gate.

**Tooling (proposed 2026-06-20, spec in `PLAN.md` §8 / `DISCUSSION_NOTES.md` Block 38):**
- **Dedicated visualization dashboard** — a project-only dashboard to watch the system work in detail; centerpiece is the *living graph* (nodes=models, edges=connections coloured by pathway-reputation, animated belief-flow), plus node inspector, pathway leaderboard, evaluator/test panel, regime ribbon, evolution feed, and belief-space stream. Domain-agnostic core + a separate stock-specific "Adapter View" tab (per Rule 23). ✅ stack ratified (Block 43); walking skeleton + Adapter-View tab built (Blocks 43-44).
